# ของเดิม — เก็บไว้อ้างอิงอย่างเดียว **ห้าม apply**

สองไฟล์นี้คือ manifest ที่ใช้อยู่บน cluster เดิม เก็บไว้เพื่อ 2 อย่าง:

1. **ใช้เทียบ** ว่าของใหม่ในโฟลเดอร์แม่เปลี่ยนอะไรไปบ้าง — ตารางเทียบเต็มอยู่ที่
   [บทที่ 11 หัวข้อ 2](../../../docs/11-deploy-app.md)
2. **ใช้ย้อนกลับ** ถ้าของใหม่มีปัญหาระหว่างย้าย (แต่ย้อนไปที่ cluster เดิม ไม่ใช่ cluster ใหม่)

> 🔴 **apply ลง `myhr-prod` ของ cluster ใหม่ไม่ได้ และไม่ควรลอง**
> PSA `restricted` จะบล็อกตั้งแต่ `runAsUser: 0` และถึงจะผ่านก็ยังขาด PDB, resources,
> probe และ topology spread ซึ่งเป็นของที่ทำให้ `kubectl drain` ทุก 1-2 เดือนไม่ทำ service ดับ
>
> **อย่าเปลี่ยนนามสกุลเป็น `.yaml`** — ข้อ 2-6 ของ `validate-manifests.sh` อ่านเฉพาะ `*.yaml` ไฟล์ที่นี่จึงถูกข้ามไป
> (ข้อ 1 kubeconform อ่าน `.yml` ด้วยแต่ผ่าน เพราะ schema ของเก่าก็ถูกต้องอยู่)
> ถ้าเปลี่ยนเป็น `.yaml` เมื่อไหร่ CI จะตกทันที (`runAsUser: 0` · ไม่มี PDB · ไม่มี probe)
