ทำที่บทไหน 03 05 + 07

🔴 HAProxy กับ keepalived ไม่แตะทราฟฟิกของแอปแม้แต่นิดเดียว — คนที่เปิดเว็บ ไม่เคยวิ่งผ่าน .100 เลย เข้าใจผิดข้อนี้แล้วจะไล่ปัญหาผิดทางทั้งกระบวน

failure domain แยกกันสนิท: · VIP ล่ม → kubectl ใช้ไม่ได้ deploy ไม่ได้ แต่ pod ที่รันอยู่และผู้ใช้ยังปกติ · L2 announcement ล่ม → ผู้ใช้เข้าไม่ได้ แต่ cluster ข้างในปกติ ยัง kubectl ได้

"เข้าเว็บไม่ได้" กับ "kubectl ไม่ได้" แทบไม่เคยมีสาเหตุเดียวกัน

เอา Gateway ไปอยู่หลัง VIP เลยไม่ได้เหรอ — ได้ทางเทคนิค แต่จะบีบทราฟฟิกแอปทั้งหมด ผ่าน HAProxy ตัวเดียวบน master เครื่องเดียว ทำให้ master เป็นคอขวดของทั้งระบบ และทำลายเหตุผลที่เลือก Cilium LB-IPAM ตั้งแต่แรก

บน Windows บล็อกข้างบนใช้ไม่ได้ — มันเป็นไวยากรณ์ของ bash (Git Bash / WSL / เครื่อง Linux) ถ้าอยู่ใน PowerShell ให้ใช้อันนี้แทน:

foreach ($ip in 101..106) {
  ssh root@192.168.50.$ip "mkdir -p /root/k8s"
  scp -r docs/versions.env config "root@192.168.50.${ip}:/root/k8s/"
}
bash

🔴 PowerShell 5.1 ไม่มี && — คำสั่งที่ต่อกันด้วย && (ซึ่งใช้ได้ปกติเมื่อรันบน node) จะขึ้น The token '&&' is not a valid statement separator in this version. ให้แยกเป็นคนละบรรทัด หรือใช้ ; แทน (ต่างกันตรงที่ ; รันต่อแม้อันก่อนหน้าจะล้มเหลว) · และปลายทางที่มี $ip ต้องเขียนเป็น "...${ip}:/root/k8s/" ไม่งั้น PowerShell จะอ่าน $ip: เป็นตัวแปรแบบระบุ scope แล้วพัง

ต้องรันซ้ำทุกครั้งที่แก้ไฟล์ในrepo ไม่ใช่ครั้งเดียวตอนเริ่ม — ไม่งั้นบทที่กำลังทำ จะอ้างไฟล์ที่ยังไม่มีบนเครื่อง แล้วเจอ does not exist กลางคัน ทุกบทมีคำสั่งตรวจไฟล์ของตัวเองอยู่ที่ขั้นที่ 0

กติกา 6 ข้อของคู่มือชุดนี้

✓

1 · ทุกเวอร์ชันมาจาก versions.env เท่านั้น รันบรรทัดนี้ก่อนเริ่มทุก session บนทุกเครื่อง — ถ้าลืม คำสั่งจะ error ทันทีเพราะตัวแปรว่าง ซึ่งดีกว่าเผลอไปติดตั้งเวอร์ชันผิด

set -a && source /root/k8s/versions.env && set +a
bash

2 · ทุกคำสั่งมี "ผลลัพธ์ที่ควรเห็น" ถ้าผลไม่ตรง ให้หยุดตรงนั้น อย่าไปต่อแล้วค่อยกลับมาแก้

3 · ไม่มีความลับในไฟล์นี้ password, token และ key ทั้งหมดเป็น placeholder ค่าจริงอยู่ในที่เก็บ secret แยก

4 · ห้าม kubectl edit บน cluster ตรง ๆ ทุกอย่างที่ apply ต้องมาจากไฟล์ใน git เพราะเราไม่มี GitOps มาบังคับให้

5 · ทุกคำสั่ง copy เขียนเป็น \cp -f เสมอ — ไม่ใช่ cp บน Oracle Linux root มี alias cp='cp -i' ติดมาจาก /root/.bashrc พอ copy ทับไฟล์ที่มีอยู่แล้ว มันจะถาม cp: overwrite '...'? แล้วรอคำตอบ — ถ้าไม่ได้ตอบ y เป๊ะ ๆ มันจะยกเลิกเงียบ ๆ ไม่มี error ให้เห็น ของเดิมยังอยู่ที่เดิมทั้งที่คุณคิดว่าทับไปแล้ว เวลาวางคำสั่งทีละหลายบรรทัด คำถามนี้จะโผล่กลางกอง แล้วมักโดนกด Enter ผ่านไปโดยไม่ทันสังเกต

\ หน้าคำสั่งบังคับให้ใช้ binary จริงแทน alias — ใส่ -f เฉย ๆ ไม่พอ เพราะ cp -i -f ยังถามอยู่

6 · หลังวางไฟล์ config ใช้ systemctl restart เสมอ — ไม่ใช่ enable --now --now จะ start ให้เฉพาะตอนที่ service ยังไม่รัน ถ้ามันรันอยู่แล้ว คำสั่งจะผ่านไปเงียบ ๆ โดยไม่โหลด config ใหม่ — คุณจะเห็น active (running) แต่มันยังถือไฟล์เก่าอยู่

systemctl enable <service>     # ให้ขึ้นเองตอน boot
systemctl restart <service>    # โหลด config ที่เพิ่งวาง — ถูกทั้งกรณีรันอยู่และยังไม่รัน
bash

ความจริงสองข้อที่ส่งผลกับทุกอย่างหลังจากนี้

✓

ไม่มี Ksplice — ใช้ Oracle Linux แบบฟรี จึงปะ kernel โดยไม่ reboot ไม่ได้ แปลว่าต้อง drain ทุก node ทุก 1-2 เดือน ผลคือ ทุก Deployment ต้องมี PodDisruptionBudget และ replica ≥ 2 ไม่ใช่ข้อแนะนำแต่เป็นข้อบังคับ

Cilium ถือ 3 หน้าที่พร้อมกัน — CNI + kube-proxy + LB-IPAM ทำให้ชิ้นส่วนน้อยลงมาก แต่แลกมาด้วยว่า Cilium มีปัญหาทีเดียว pod network, Service และ LoadBalancer ดับพร้อมกัน และ ไม่มี kube-proxy ให้ถอยกลับไปใช้ เพราะไม่ได้ติดตั้งไว้เลย
